## 9. 訊息模板管理

**操作路徑**：左側導航欄 → 「訊息模板」

系統內置 App 訊息中心的業務模板。模板類型由系統定義，後台用於選擇模板、維護多語言標題和正文、核對變數、預覽草稿及儲存文案。

### 9.1 模板列表

左側模板列表顯示模板名稱、業務分類和版本。先按業務事件選擇模板，再檢查右側標題中的模板名稱、分類、版本及更新時間，避免編輯同名但觸發對象不同的模板。

常見類別包括：

| 類別 | 典型事件 |
| --- | --- |
| **換匯** | 提交、完成、執行失敗或拒絕 |
| **入金 / 出金** | 入賬、通過、拒絕或待補資料 |
| **轉倉 / 股票轉讓** | 提交、初審、終審、待接收方確認、完成、取消或拒收 |
| **訂單** | 成交、取消或拒絕 |
| **帳戶安全** | 電郵、登入密碼或交易密碼變更提醒 |
| **系統** | 系統公告及其他平台事件 |

「重新整理」用於重新載入系統定義的模板清單。執行後應重新選擇目標模板，確認未切換到其他版本。

### 9.2 模板編輯

1. 從左側選擇目標模板；
2. 查看「可用變數」，區分必填變數與可選變數；
3. 選擇繁體中文、簡體中文或英文標籤；
4. 修改「站內訊息標題」和「站內訊息正文」；
5. 對照其他語言檢查含義、金額、幣種和狀態是否一致；
6. 使用測試 Payload 預覽；
7. 複核無誤後點擊「儲存」。

### 9.3 變數規則

- 變數使用頁面顯示的完整名稱和括號格式，例如 `{{exchangeId}}`；
- 標記為「必填」的變數必須保留，否則實際訊息可能缺少關鍵內容；
- 不要自行改名、翻譯變數或加入後台未提供的變數；
- 同一變數在標題和正文中的含義應一致；
- 範例 Payload 只使用虛構測試值，不要貼上真實用戶、訂單或帳戶資料。

### 9.4 預覽草稿

在 Payload JSON 中為頁面列出的變數提供測試值，點擊「預覽草稿」。預覽只用於檢查當前草稿的呈現結果，不代表訊息已發送。

檢查：

1. JSON 格式有效，欄位名稱與變數完全一致；
2. 預覽中沒有殘留的 `{{变量}}`；
3. 金額、幣種、數量、用戶稱謂和狀態文案自然；
4. 三種語言均無截斷、錯譯或混用；
5. 標題和正文表達的是同一個業務結果。

### 9.5 儲存邊界

「儲存」會修改模板文案，可能影響後續真實通知。儲存前應按組織流程完成文案複核；本頁面不用於手動給用戶發送單則訊息。若預覽異常，先修正變數或 Payload，不要反覆儲存未驗證的版本。
