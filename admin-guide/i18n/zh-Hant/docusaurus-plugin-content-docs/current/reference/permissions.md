## 角色權限與操作邊界

系統使用三類角色。實際可見選單還會受到部署版本、帳號狀態和組織授權影響；當頁面權限與本表不一致時，以更嚴格的邊界為準，並聯繫授權負責人確認。

| 能力 | 投資者 | 管理員 | 超級管理員 |
| --- | :---: | :---: | :---: |
| 使用客戶端查看本人帳戶和業務 | ✓ | 依帳戶本身 | 依帳戶本身 |
| 登入管理員後台 | — | ✓ | ✓ |
| 查詢投資者、客戶、股票和市場資料 | — | 在獲授權範圍內 | ✓ |
| 查看記錄與審計日誌 | — | 在獲授權範圍內 | ✓ |
| 執行業務初審 | — | 在獲授權範圍內 | ✓ |
| 編輯並提交匯率或系統設定審核 | — | 在獲授權範圍內 | ✓ |
| 對高風險記錄或設定進行終審 | — | — | ✓ |
| 變更後台角色 | — | — | 僅限獲授權的超級管理員 |

`✓` 表示角色具備該類能力的基礎條件，不代表每次操作都已獲業務授權；`—` 表示不應透過該角色執行。

### 角色變更

1. 使用姓名、手機號碼和 VC User ID 精確定位用戶；
2. 核對當前角色、目標角色和審核依據；
3. 只授予完成崗位職責所需的最低角色；
4. 變更後要求用戶重新登入，並驗證可見選單；
5. 在審計日誌中核對操作人、目標用戶、時間和結果。

:::warning 高風險操作
角色提升、系統設定、匯率和資金或持倉相關終審不得由同一人繞過審核鏈完成。頁面存在按鈕不等於當前人員已獲得業務授權。
:::

### 審計與追溯

角色變更、審核和設定操作完成後，應在審計日誌中核對記錄。使用操作人、目標用戶、資源 ID、結果和時間範圍縮小查詢；失敗記錄也應保留並調查原因。

### 權限回收

出現崗位變更、離職、帳號共用、異常登入或授權到期時，應立即透過組織審核流程降權或撤銷訪問，並檢查近期審計日誌。不要僅透過修改顯示名稱來代替權限回收。

### 聯繫支援

本倉庫未提供可驗證的公開技術電郵或熱線。遇到技術故障、業務疑問或安全事件時，請透過組織已授權的內部支援、值班或升級流程聯繫相關人員，不要使用文檔中的歷史佔位聯繫方式。

提交問題時建議提供：

- 發生時間、環境和當前路由；
- 當前帳號角色（不要提供密碼或驗證碼）；
- 可復現步驟與頁面錯誤文字；
- 相關業務記錄 ID 或審計日誌 ID；
- 已脫敏的截圖或日誌。
