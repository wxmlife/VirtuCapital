## 角色权限与操作边界

系统使用三类角色。实际可见菜单还会受到部署版本、账号状态和组织授权影响；当页面权限与本表不一致时，以更严格的边界为准，并联系授权负责人确认。

| 能力 | 投资者 | 管理员 | 超级管理员 |
| --- | :---: | :---: | :---: |
| 使用客户端查看本人账户和业务 | ✓ | 依账户本身 | 依账户本身 |
| 登录管理员后台 | — | ✓ | ✓ |
| 查询投资者、客户、股票和市场资料 | — | 在获授权范围内 | ✓ |
| 查看记录与审计日志 | — | 在获授权范围内 | ✓ |
| 执行业务初审 | — | 在获授权范围内 | ✓ |
| 编辑并提交汇率或系统设定审核 | — | 在获授权范围内 | ✓ |
| 对高风险记录或设定进行终审 | — | — | ✓ |
| 变更后台角色 | — | — | 仅限获授权的超级管理员 |

`✓` 表示角色具备该类能力的基础条件，不代表每次操作都已获业务授权；`—` 表示不应通过该角色执行。

### 角色变更

1. 使用姓名、手机号和 VC User ID 精确定位用户；
2. 核对当前角色、目标角色和审批依据；
3. 只授予完成岗位职责所需的最低角色；
4. 变更后要求用户重新登录，并验证可见菜单；
5. 在审计日志中核对操作人、目标用户、时间和结果。

:::warning 高风险操作
角色提升、系统设定、汇率和资金或持仓相关终审不得由同一人绕过审批链完成。页面存在按钮不等于当前人员已获得业务授权。
:::

### 审计与追溯

角色变更、审核和配置操作完成后，应在审计日志中核对记录。使用操作人、目标用户、资源 ID、结果和时间范围缩小查询；失败记录也应保留并调查原因。

### 权限回收

出现岗位变更、离职、账号共用、异常登录或授权到期时，应立即通过组织审批流程降权或撤销访问，并检查近期审计日志。不要仅通过修改显示名称来代替权限回收。

### 联系支持

本仓库未提供可验证的公开技术邮箱或热线。遇到技术故障、业务疑问或安全事件时，请通过组织已授权的内部支持、值班或升级流程联系相关人员，不要使用文档中的历史占位联系方式。

提交问题时建议提供：

- 发生时间、环境和当前路由；
- 当前账号角色（不要提供密码或验证码）；
- 可复现步骤与页面错误文字；
- 相关业务记录 ID 或审计日志 ID；
- 已脱敏的截图或日志。
