## 9. 消息模板管理

**操作路径**：左侧导航栏 → 「消息模板」

系统内置 App 消息中心的业务模板。模板类型由系统定义，后台用于选择模板、维护多语言标题和正文、核对变量、预览草稿及保存文案。

### 9.1 模板列表

左侧模板列表显示模板名称、业务分类和版本。先按业务事件选择模板，再检查右侧标题中的模板名称、分类、版本及更新时间，避免编辑同名但触发对象不同的模板。

常见类别包括：

| 类别 | 典型事件 |
| --- | --- |
| **换汇** | 提交、完成、执行失败或拒绝 |
| **入金 / 出金** | 入账、通过、拒绝或待补资料 |
| **转仓 / 股票转让** | 提交、初审、终审、待接收方确认、完成、取消或拒收 |
| **订单** | 成交、取消或拒绝 |
| **账户安全** | 邮箱、登录密码或交易密码变更提醒 |
| **系统** | 系统公告及其他平台事件 |

「重新整理」用于重新加载系统定义的模板清单。执行后应重新选择目标模板，确认未切换到其他版本。

### 9.2 模板编辑

1. 从左侧选择目标模板；
2. 查看「可用变量」，区分必填变量与可选变量；
3. 选择繁体中文、简体中文或英文标签；
4. 修改「站内消息标题」和「站内消息正文」；
5. 对照其他语言检查含义、金额、币种和状态是否一致；
6. 使用测试 Payload 预览；
7. 复核无误后点击「储存」。

### 9.3 变量规则

- 变量使用页面显示的完整名称和括号格式，例如 `{{exchangeId}}`；
- 标记为「必填」的变量必须保留，否则实际消息可能缺少关键内容；
- 不要自行改名、翻译变量或加入后台未提供的变量；
- 同一变量在标题和正文中的含义应一致；
- 示例 Payload 只使用虚构测试值，不要粘贴真实用户、订单或账户资料。

### 9.4 预览草稿

在 Payload JSON 中为页面列出的变量提供测试值，点击「预览草稿」。预览只用于检查当前草稿的渲染结果，不代表消息已发送。

检查：

1. JSON 格式有效，字段名称与变量完全一致；
2. 预览中没有残留的 `{{变量}}`；
3. 金额、币种、数量、用户称谓和状态文案自然；
4. 三种语言均无截断、错译或混用；
5. 标题和正文表达的是同一个业务结果。

### 9.5 保存边界

「储存」会修改模板文案，可能影响后续真实通知。保存前应按组织流程完成文案复核；本页面不用于手动给用户发送单条消息。若预览异常，先修正变量或 Payload，不要反复保存未验证的版本。
